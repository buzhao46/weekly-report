## 0. 配套产物

| 产物 | 路径 | 用途 |
| --- | --- | --- |
| Design Token 层 | `public/style.css` `:root` | 所有设计决策的唯一事实来源（SSOT） |
| 活样式指南 | `public/design-system.html`（浏览器访问 `/design-system.html`） | 真实渲染所有组件，供设计走查与开发对照 |
| 本规范 | `docs/design-system-v1.0.md` | 书面依据与验收标准 |

**三条系统级原则**（与 PRD 的产品原则对齐）：

1. **克制**：单实例、单团队、无社交属性——视觉上不做装饰性渐变、大插画、动效堆砌；信息密度优先。
2. **一致**：任何新 UI 一律从 Token 取值，禁止在组件里写裸色值/裸字号/裸圆角。
3. **可达**：默认满足 WCAG AA（正文对比 ≥ 4.5:1），键盘可达，触控目标 ≥ 36px（键盘场景为主的内部工具，44px 为推荐值）。

- 语义色只表达状态（成功/警告/危险），不做装饰。

- 禁止引入色阶之外的新颜色；确需新增 → 先进 Token 层，再使用。

### 1.2 字体

| Token | 值 | 用途 |
| --- | --- | --- |
| `--fs-meta` | `12px` | 徽标、计数器、日志时间等元信息 |
| `--fs-small` | `13px` | 次级正文、说明文字 |
| `--fs-control` | `13.5px` | 按钮、输入框、表格单元格 |
| `--fs-base` | `14px` | 正文基准 |
| `--fs-title` | `20px` | 页面标题 |

- 字体族：`-apple-system, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`（系统栈，零加载成本；本产品为本地单体应用，禁止引入 Web Font）。
- 等宽（临时口令展示）：`ui-monospace, Consolas, monospace`（`.temp-pwd`）。
- 字重：400 正文 / 500 次强调 / 600 标题与按钮 / 700 评分数字与品牌标。
- 行高：正文 1.6；评论与详情正文 1.7–1.8。
- 数字一律 `font-variant-numeric: tabular-nums`（评分、表格数字列）。

## 2. 组件规范

> 以下全部组件在 `/design-system.html` 有真实渲染示例，视觉以该页为准。

### 2.1 按钮 `.btn`

| 变体 | 类名 | 场景 |
| --- | --- | --- |
| 主要 | `.btn-primary` | 每屏**至多一个**：登录、保存并提交、新建周报、新增成员 |
| 默认 | `.btn` | 次要操作：取消、导出、重置口令 |
| 幽灵 | `.btn-ghost` | 行内/工具条弱操作 |
| 危险 | `.btn-danger` | 删除周报、删除评论、停用成员（需二次确认） |
| 小号 | `.btn-sm` | 表格行内操作 |

**状态**：hover 加深底色；disabled `opacity .5` + 禁指针；`padding 7px 14px`，`--radius-sm`~8px。危险按钮必须配合确认弹层或输入确认，不得单击即删。

### 2.2 表单 `.field`

- 标签 `.field-label` 13px/600；hint `.field-hint` 12.5px 弱化色，放标签右侧。
- 输入框：`border --gray-300`、`--radius-sm` 档、`padding 9px 11px`；focus = 主色边框 + `--focus-ring`。
- 文本域：上周总结 `min-height 120px`，本周计划 100px；带 `.counter` 字数提示（右浮、12px）。
- 错误反馈：红字置于字段下方（`--color-danger`，12.5px），输入框边框同步变红；**禁止只用 toast 报字段错误**。

### 2.3 徽标 `.badge`

| 变体 | 类名 | 语义 |
| --- | --- | --- |
| 默认 | `.badge` | 中性（权限明细等） |
| 未提交 | `.badge-draft` | 黄系（警告底+警告字） |
| 已提交 | `.badge-submitted` | 绿系（成功底+成功字） |
| 可查看 | `.badge-view` | 中性灰 |
| 可评论 | `.badge-comment` | 蓝系 |
| 管理员 | `.badge-admin` | 紫系（唯一紫色使用点） |

规则：徽标只做状态与权限标注，颜色即语义，不得挪作装饰；胶囊 `--radius-full`、12px 字、`padding 2px 8px`。

### 2.4 自我评分（本产品核心组件）

- **列表胶囊 `.score`**：pos（蓝）/ zero（灰）/ neg（橙）/ none（未评分，灰字无底）。正负用「蓝=正、橙=负」——**刻意避开红绿**，防止与危险/成功语义冲突。
- **编辑滑杆 `.score-box`**：-5~+5 十一档；轨道渐变隐喻负→零→正；滑块 20px 白底蓝边；`.ticks` 两端标注 -5 / +5；`.score-value` 实时回显，未评分为 `.none` 态。
- 空值语义：null = 未评分（`--text-faint` 展示「未评分」），0 是有效评分不是空。

### 2.5 表格

- 表头：`--gray-25` 底、12.5px/600 次级色、`white-space: nowrap`。
- 行：`padding 11px 14px`，分隔线 `#f0f2f5`（v1.1 归入 `--gray-200` 淡化档）；hover `--gray-25`。
- 数字列 `td.num` 用 tabular-nums；行内操作放行尾、用 `.btn-sm`，间距 6px。
- 长表必须包 `.table-scroll` 允许横向滚动，禁止压缩列。

### 2.6 提示 / 空态 / Toast

- `.notice`：左 3px 色条信息条（蓝=说明，`--warn` 变体=警告）；用于「临时口令首次登录需修改」等场景。
- `.empty-state`：56px 上下留白、居中、标题 15px + 一句说明 + 可选动作按钮；空态文案禁止卖萌和指責用户（写「暂无周报，点击右上角新建」而非「你还没写过周报哦~」）。
- `.toast`：固定底部居中，深底白字；`ok` 绿深底 / `err` 红深底；**只用于操作结果反馈**（已保存/已删除/失败原因），不用于字段级校验。
- **统一越权提示**（PRD F13）：无权限与不存在展示同一套空态样式与文案「无权访问或内容不存在」，不泄露区分信息。

### 2.7 变更记录 / 评论（详情页）

- `.changelog`：每条=圆点（按类型配色）+ 一句话描述 + 时间/操作人元信息；字段级 diff 用 `pre.log-old` / `pre.log-new` 双色块，长文截断给 `.log-trunc` 提示。
- `.comment`：作者 600 加粗 + 12px 时间 + 正文 13.5px；自己的评论才有删除按钮。
- 权限类变更记录按 PRD C02 脱敏：只显示「权限名单有调整」，不显示具体人员增删。

## 3. 状态与交互模式

| 状态 | 规范 |
| --- | --- |
| Loading | 首屏 `.app-loading` 文案式占位；表单提交按钮进入 disabled + 文案「保存中…」，不引入旋转图标 |
| Focus | 所有可交互元素必须有可见焦点：输入类用 `--focus-ring`；按钮/链接依赖浏览器默认 outline，**禁止全局去掉 outline** |
| Disabled | `opacity .5` + `cursor: not-allowed`，并保留语义（临时口令态未完成不得放行业务页） |
| 空态 | 见 2.6 |
| 错误 | 字段级红字 + 边框红；操作级 toast err；越权级统一空态 |

## 4. 可访问性（WCAG AA）

### 4.1 对比度审计（v1.0 实测）

| 组合 | 对比度 | 结论 |
| --- | --- | --- |
| `--gray-900` 正文 / 白 | ≈ 16:1 | ✅ |
| `--gray-600` 次级 / 白 | ≈ 6.4:1 | ✅ |
| 白字 / `--accent-500` 主按钮 | ≈ 4.6:1 | ✅ |
| `--gray-400` 弱化文字 / 白 | ≈ 3.1:1 | ⚠️ 仅限辅助说明，**不得承载必读信息** |
| `--color-warning` / `--color-warning-soft`（未提交徽标） | ≈ 3.4:1 | ❌ 不达 4.5:1 |
| `--color-success` / `--color-success-soft`（已提交徽标） | ≈ 4.2:1 | ❌ 略不达标 |
| `--accent-500` / `--accent-soft`（可评论徽标） | ≈ 4.1:1 | ❌ 略不达标 |

### 4.2 整改方案（v1.1，P1 待办）

徽标文字加深，底色不变，视觉风格不变：

```css
--color-warning-text: #8a5a12;  /* 替换 badge-draft 前景 */
--color-success-text: #22703f;  /* 替换 badge-submitted 前景 */
--accent-badge-text:  #2458c7;  /* 替换 badge-comment 前景 */
```

### 4.3 其他硬性要求

1. **键盘可达**：登录表单 Enter 提交；权限双栏 checkbox 可 Tab 遍历；滑杆可用方向键逐档调整（原生 `input[type=range]` 已满足，不得自绘替换）。
2. **触控目标**：行内 `.btn-sm` 实际命中区 ≥ 36×36px（padding 不足时用透明外扩），44px 为推荐值。
3. **语义与读屏**：列表用真实 `<table>`；徽标文字自描述（「未提交」而非色点）；删除等危险操作按钮文字完整（不带图标含义）。
4. **文本缩放**：布局在 200% 浏览器字号下不横向溢出（表格允许滚动，其余禁止 `height` 锁死）。
5. **动效敏感**：全站动效仅 120ms 颜色/阴影过渡，天然满足 `prefers-reduced-motion`；禁止引入位移类动画。

## 5. 命名与演进规则

1. **Token 命名**：`--{类别}-{档位}`（如 `--gray-200`、`--space-4`、`--fs-title`、`--radius-md`）；语义别名（`--text`、`--bg`、`--border`）视为对 Token 的引用，组件样式**优先引用语义别名**。
2. **组件类名**：Burt 简化 BEM（`badge-draft`、`notice-warn`），不加新前缀体系。
3. **新增颜色的流程**：先在 `:root` 定义 Token → 本规范补表格 → 才能在组件中使用。
4. **版本演进**：本规范随代码走，改样式必须同步改本文件与 `design-system.html`；v1.1 已列待办（徽标对比度、圆角归档、非标间距清理）。
5. **禁止事项**：组件内裸写色值 / 字号 / 圆角；引入第二套阴影；添加 >200ms 动效；删除 focus outline。
