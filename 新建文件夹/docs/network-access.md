# 跨网访问说明（局域网 / 公网）

本项目是单机 Node 服务，默认监听 `0.0.0.0:3000`（所有网卡），因此同网段的同事可以直接用你的内网 IP 访问。
`HOST=127.0.0.1` 可回退为「仅本机可访问」。

启动后控制台会打印所有可用地址，形如：

```
周报平台已启动（监听 0.0.0.0:3000）
本地数据库: D:\工作周报平台\data\weekly-report.db
可访问地址：
  本机     http://127.0.0.1:3000
  局域网   http://192.168.1.23:3000   (以太网)
```

---

## 一、同网段（同一路由器/交换机下）访问

1. 在运行服务的电脑上启动：`npm start`（或 `node --no-warnings server.js`）。
2. 记下控制台里「局域网」那一行的地址，例如 `http://192.168.1.23:3000`。
3. 让同一网段的同事在浏览器里直接打开这个地址即可。
4. 如果打不开，按下面顺序排查：
   1. 确认对方和服务器在**同一网段**（前三段 IP 相同，如都是 `192.168.1.x`）；
   2. 在服务器上用 `ipconfig` 确认 IP 没有变化（DHCP 可能导致 IP 变动，建议在路由器上给这台机器绑定固定 IP）；
   3. 在服务器本机浏览器打开 `http://127.0.0.1:3000` —— 打不开说明是服务本身没起来；
   4. 在客户端 `ping 192.168.1.23` —— 不通说明是网络/网段问题，不是程序问题；
   5. 以上都正常但仍打不开，基本是 **Windows 防火墙**拦了端口，见第二节。

> 只在「本机」访问时，请用 `HOST=127.0.0.1` 启动，避免无意中把服务暴露给整个网段。

---

## 二、Windows 防火墙放行端口

以**管理员身份**打开 PowerShell 或 CMD，执行（把端口改成你实际使用的 `PORT`）：

```bat
netsh advfirewall firewall add rule name="周报平台 3000" dir=in action=allow protocol=TCP localport=3000
```

只允许特定网段访问（更安全，示例为 `192.168.1.0/24`）：

```bat
netsh advfirewall firewall add rule name="周报平台 3000 内网" dir=in action=allow protocol=TCP localport=3000 remoteip=192.168.1.0/24
```

删除规则 / 临时关闭：

```bat
netsh advfirewall firewall delete rule name="周报平台 3000"
netsh advfirewall set allprofiles state off   :: 仅临时测试用，正式环境不要关
```

另外：第一次运行 `node` 时 Windows 可能弹出「防火墙已阻止此应用的部分功能」，请勾选**专用网络**并允许访问，
否则即使加了端口规则也可能被拦截（此时在「允许应用通过防火墙」里放行 Node.js 即可）。

## 三、跨路由器访问（外网访问）

**这一步程序本身做不到。** 要求你的网络满足：

- 有一条**公网 IP** 的宽带线路（家用宽带常是运营商 NAT 后的"内网 IP"，需要向运营商申请公网 IP，或改用内网穿透/组网工具）；
- 在**路由器**上把外网端口转发到这台电脑的内网 IP + 端口（端口映射 / 端口转发 / Virtual Server）。

一般步骤（不同路由器菜单名略有差异，通常位于「高级设置 → 端口转发 / NAT / 虚拟服务器」）：

1. 给运行服务的电脑绑定**固定内网 IP**（在路由器里做 DHCP 静态分配，或在系统里设静态 IP），例如 `192.168.1.23`。
2. 在路由器新建端口转发规则：
   - 外部端口：建议用非默认端口，例如 `38000`（不要用 3000/80，减少被扫描）；
   - 内部 IP：`192.168.1.23`；
   - 内部端口：`3000`；
   - 协议：TCP。
3. 用手机流量（**不要连同一个 Wi-Fi**）访问 `http://<你的公网IP>:38000` 验证。
4. 公网 IP 每次拨号可能变化，建议在路由器里开启 **DDNS**（动态域名），这样用 `http://yourname.ddns.net:38000` 访问即可。
5. 排查顺序（逐层确认，前一步不通就不要看下一步）：
   1. 内网能访问（同网段另一台机器打开成功）→ 服务与防火墙没问题；
   2. 路由器 WAN 口拿到的 IP 是公网地址（在 `ipconfig` 里看到的地址若形如 `10.x` / `100.64.x` / `172.16~31.x` / `192.168.x`，通常是运营商内网，需要打客服申请公网 IP）；
   3. 端口转发规则的内外端口、协议、内部 IP 都没填错（最容易错的是内部 IP 填成了路由器的 IP）；
   4. 用手机流量访问公网 IP:端口，若仍不通，可能是运营商封了该端口（换端口试试）或有二级路由（光猫桥接/双重 NAT，需要在光猫上也做一次转发）；
   5. 若公司/校园网，通常无法做端口映射，请改用 VPN 或内网穿透工具。

## 四、安全警告（务必阅读）

1. **本服务使用 HTTP 明文传输。** 口令、周报正文、评论内容在链路上都是明文，任何能截获流量的人（同一个公共 Wi-Fi、
   同一交换机、链路上的运营商或中间设备）都能直接看到，口令可被拿去登录。
2. 因此：**只在可信内网使用，或通过 VPN/组网工具（如公司 VPN、Tailscale 等）访问**。不要在公共 Wi-Fi、
   咖啡厅网络、展会网络等环境下开端口。
3. 如果确实需要暴露到公网，请在前面加一层 **HTTPS 反向代理**（如 Nginx / Caddy / IIS ARR）：
   - 由反向代理持有证书（可用 Let's Encrypt 免费证书）并用 443 端口对外；
   - 本服务继续只监听 `127.0.0.1:3000`，由反向代理转发到本机；
   - 这样口令和正文在公网链路上是加密的。
   具体做法不在本项目范围内。
4. **管理员初始口令必须修改。** 服务监听非本机地址且管理员仍使用初始口令时，启动日志会打印醒目的安全警告。
   请立刻登录 → 改口令；同时在「成员管理」里为每个人设置独立账号，不要共用管理员。
5. 本服务没有内置限流、审计和登录验证码（仅有 5 次失败锁定 1 分钟）。公网暴露会显著提高被暴力破解的风险。
6. 数据全在本机 `data/weekly-report.db`，请自行做好备份（导出功能可用来导出可读副本）。
